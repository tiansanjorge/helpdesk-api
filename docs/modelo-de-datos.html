Modelo de datos

Borrador del esquema de helpdesk-api: 8 tablas, multi-tenant por organizationId. Refleja prisma/schema.prisma.

  • Clave primaria
  • Referencia a Organization (en todas las tablas)
  • Referencia a User
  • Referencia dibujada con línea
  • Obligatoria
  • Opcional
  • 1 a N: un lado tiene uno, el otro muchos
Decisiones tomadas
  • IDs como uuid versión 7 (ordenables por tiempo).
  • Email de User único a nivel global, guardado en minúsculas.
  • Número de ticket por organización (#1, #2…): Ticket.number más el contador Organization.ticketSeq, que se incrementa de forma atómica al crear el ticket. Único por (organizationId, number).

Al borrar

  • Ticket → Comment, Attachment, ActivityLog: CASCADE
  • Customer con tickets: RESTRICT (se bloquea)
  • Category con tickets: SET NULL (propuesto)
  • User: no se borra, se desactiva con isActive = false

Índices y únicos

  • Ticket (organizationId, status, createdAt): listado filtrado
  • Ticket (organizationId, assigneeId, status): mis tickets
  • Ticket (organizationId, customerId): historial del cliente
  • Comment (ticketId, createdAt), ActivityLog (ticketId, createdAt), Attachment (ticketId)
  • Ticket (categoryId): para el SET NULL al borrar una categoría
  • Único: Ticket (organizationId, number), Customer (organizationId, email), Category (organizationId, name)

Enums

  • role: ADMIN, AGENT
  • status: OPEN, IN_PROGRESS, RESOLVED, CLOSED
  • priority: LOW, MEDIUM, HIGH, URGENT
  • action: STATUS_CHANGED, ASSIGNED… (a definir)
